## GitHub Pages deployment

The repository includes `.github/workflows/pages.yml`. A push to `main` builds a static `_site` bundle and deploys it through GitHub Pages. In the repository settings, select **GitHub Actions** as the Pages source. All map, picker, waypoint, airspace, manual-traffic and browser RTL-SDR features use repository-relative URLs and therefore work under the normal `https://<owner>.github.io/<repository>/` subpath.

GitHub Pages cannot execute `radio-watch-server.js`. To retain live ADS-B/OGN traffic and METAR, deploy the included Node relay separately over HTTPS and create the repository Actions variable `R4DIO_DASH_API_BASE` with its origin, for example `https://r4dio-dash-cz.onrender.com`. The Pages build writes that origin into the generated site without modifying the source `index.html`. The `?apiBase=https://...` query override remains available for testing. Without a relay, the static application still loads normally and reports that its live-data relay is not configured instead of requesting a nonexistent Pages route and displaying an HTTP 404.

Run `npm run build:pages` to produce the same `_site` bundle locally. The generated directory is ignored by Git.

For the complete relay deployment, verification URLs, GitHub variable setup,
Pages rebuild, and troubleshooting sequence, follow
[`GITHUB_PAGES_TRAFFIC_SETUP.md`](GITHUB_PAGES_TRAFFIC_SETUP.md).

## Publishing the complete Node website

The complete application is a small Node web service, not a static-only site. The browser UI, Czech CUP/CUB datasets, Three.js renderer, ADS-B/OGN relay, and METAR relay should be published together so all requests use the same HTTPS origin. `package.json` and `render.yaml` are included for this purpose.

Recommended deployment:

1. Commit and push **all** runtime files, including `three.min.js`, `aviation-data.js`, `polygon-clipping.min.js`, both CUP/CUB datasets, `radio-watch-server.js`, `package.json`, and `render.yaml`.
2. In Render, choose **New → Blueprint** and select this repository. Render reads `render.yaml`, checks the server, starts it with Node 22, assigns HTTPS, and monitors `/api/health`.
3. Open the assigned `https://...onrender.com` address, or use that HTTPS origin as the `R4DIO_DASH_API_BASE` repository variable for the GitHub Pages frontend.
4. Confirm `/api/health`, `/api/live-traffic`, and `/api/metars` return JSON. Then enable **LIVE** in the interface; it remains off by default.

The server now follows the standard hosting `PORT` environment variable and binds to `0.0.0.0` in production. Locally, `npm start` or `node radio-watch-server.js` still binds privately to `127.0.0.1` and starts at port 8080.

If the server responds but an existing browser profile shows a blank or unresponsive app, open `http://127.0.0.1:8080/?reset=1` once. It clears only R4DIO DASH's saved browser state for that origin and then removes the reset parameter. A hard refresh (`Ctrl+F5`) also clears an older cached document. Use the exact `http://` address; live traffic and METAR require the local server rather than opening `index.html` directly.

For a manually published static frontend, set the empty `r4dio-dash-api-base` meta tag in `index.html` to the relay's HTTPS origin. The legacy `radio-watch-api-base`, `trafficEndpoint`, and `metarEndpoint` overrides remain supported for existing deployments.

## RTL-SDR connection

**Settings → SDR Receiver** contains the first hardware-facing receiver workflow for an RTL-SDR Blog V4. **SELECT / CONNECT** opens the browser's native USB chooser, restricted to the RTL2832U identity used by the V4 (`0BDA:2838`). A successful connection opens the device, claims its bulk receiver interface, and shows the product, manufacturer, USB ID, and serial reported by the dongle. **DISCONNECT** releases the interface while retaining the browser permission; **FORGET DEVICE** also asks the browser to revoke that permission.

Once the receiver interface has actually been claimed, a green **RADIO** button appears immediately to the left of **SETUP**. USB presence or retained permission alone does not reveal it. The button opens a shallow 780 × 270 resizable receiver console. Its dark retro-digital design uses cyan for navigation and controls, amber for frequency/signal information, and no additional decorative colours. The horizontal layout places the tuner, signal scope, and channel control beside one another. Neighboring frequencies are kept in a single compact preset selector rather than rendering the entire list. Full dongle identity remains available in Settings instead of consuming receiver-panel space. Select a preset—or enter any frequency from 118.000 through 136.995 MHz—and choose **START AUDIO** or **SILENT RX**. The panel includes volume control, a compact dB level bar, and a rolling signal graph. Channel changes retune while receiving. Selecting the active receiver mode again stops USB sample reads while leaving the receiver claimed for a quick restart. Disconnecting or unplugging the receiver stops reception, hides the main-window button, and changes an open radio window to **CONNECTION LOST**.

Direct USB access requires current Chrome or Edge and a secure context: the deployed site must use HTTPS, while `http://127.0.0.1:8080` and `http://localhost:8080` are accepted for local development. Opening `index.html` through `file://` is not supported. The local server explicitly grants same-origin USB permission. Only one program can own the receiver at a time, so close SDR++, SDR#, other browser windows using the dongle, and similar software before connecting. On Windows, use the official RTL-SDR Blog V4 setup guide to install the WinUSB driver for the RTL-SDR interface if the browser cannot open it.

The browser receiver uses the vendored Apache-2.0 [`@jtarrio/webrtlsdr`](https://github.com/jtarrio/webrtlsdr) low-level driver, including its RTL-SDR Blog V4/R828D input-switching implementation. R4DIO DASH runs the device at 1.024 MS/s in small 4096-sample audio blocks (about 4 ms), offsets the hardware centre by 25 kHz to avoid the zero-frequency spike, digitally shifts and filters the selected channel, envelope-demodulates AM, resamples it to the browser audio rate, and queues playback through an AudioWorklet requesting a 10 ms output path. The worklet discards audio older than 50 ms instead of allowing delayed speech to accumulate, and the squelch gate reaches audible level in roughly 1 ms. The bias tee is always left off. This is an advisory monitoring receiver, not a certified communications receiver.

The radio window also provides a graphical squelch. Its former range input has been removed: click or vertically drag the amber threshold directly on the enlarged graph. Arrow keys adjust it by 1 dB, Shift+Arrow by 5 dB, and Home/End select the limits. Silent RX opens on the first approximately 1 ms block above that threshold; closing retains hysteresis to avoid chatter. **START AUDIO** and **SILENT RX** are separate, mutually exclusive actions, and selecting the other action changes modes without releasing the channel. In normal receive mode, audio is smoothly gated while the squelch is closed. Silent RX continues receiving and detecting transmissions without playing receiver audio. It keeps the receiver at 1.024 MS/s to avoid a slow hardware mode change, uses 1024-sample detector blocks, suspends the AudioContext, and skips AM audio demodulation and waveform generation. The localhost Core Audio helper is warmed while the page loads and the mute transition uses a dedicated body-free endpoint dispatched directly from the detector edge. The graph refreshes independently at about 22 fps, so visual work does not delay detection. This prioritizes response time while avoiding audio processing, although USB throughput remains at the normal receiver rate and the RF tuner must remain powered.

On the private Windows localhost server only, opening the squelch immediately requests a mute of the computer's default multimedia output for the transmission and eight seconds after it closes. The radio console distinguishes a pending mute request from a mute confirmed by the Windows endpoint. Once the transmission ends, a smoothly draining eight-second bar remains visible for the complete muted cooldown; restoration and bridge failures are also reported explicitly. The first Silent RX selection asks for explicit in-app consent for the current page session. This is an application consent prompt, not a browser media permission: output playback and Windows Core Audio endpoint muting do not use microphone access. The feature requires `node radio-watch-server.js`; a generic static localhost server cannot expose the native Windows endpoint. Its audio-control helper is pre-warmed when the localhost page loads, remains warm, and reuses the Core Audio endpoint instead of reopening it for every transmission. The detector edge dispatches directly to dedicated `/api/system-audio/mute` and `/api/system-audio/release` routes without a JSON request-body round trip. The server records whether that output was already muted and restores the original state, and a four-second renewable safety lease restores audio if the browser, receiver, or radio window stops unexpectedly. Browsers cannot control other applications' audio on their own, so system-wide muting is intentionally unavailable on a deployed public website; Silent RX remains usable there as a silent visual receiver. The main strip now uses a fixed, unboxed **SDR RX** label; **RX** turns red and blinks while normal or Silent reception is active. Detailed readiness and error information remains available through its tooltip and the receiver controls.

## National Czech configuration

R4DIO DASH can now use any Czech waypoint in `CZ-WPT-National-XCSoar.cup` as its local reference. Click the current **airport code** in the top-left corner to:

1. search all Czech waypoints by name, code, or description;
2. set the map display range used for the initial view, nearby waypoints, and airspace suggestions;
3. choose exactly which nearby volumes from `CZ_low_plus_CE_26-04-01.cub` are rendered and monitored.

The selection, map preference, and activation state are saved locally. Each reference waypoint has a separate activation state. A direct link may preselect a coded waypoint, for example `?site=LKTB`.

The **Active Traffic** pane starts with the original compact main list and no pools. Use **ADD POOL** to create vertically stacked operational sections such as CONTACT, Fly-through, Circuit, Ground, Local traffic, Expected arrival, or any custom name. The add-pool composer includes a dedicated timer-icon shortcut for CONTACT. Creating or renaming the first pool to **CONTACT** marks it as the single contact-timer pool; its larger timer icon identifies this role, it is always operational green, and the role and green colour survive later renaming. Aircraft outside pools remain in the main list without contact alarms. Other pool colours are assigned automatically from a non-green palette. In List Edit mode, the configurable **F4** shortcut opens a keyboard-operated assignment menu for the selected aircraft; it is deliberately inactive outside F3 List Edit mode so a one-letter binding cannot intercept typing. Aircraft can also be dragged into, out of, and between pools. Escape leaves aircraft-note and Operations Notes editing, and reverses registration-field focus initiated by the focus shortcut.

Flexible airspace is state-coloured by default: inactive TRA, TSA, and TRA GA are grey; active TRA is red; active TRA GA is green; and active TSA is yellow. Danger/restricted areas remain red and MTMA remains blue. The complete palette, including the fallback colour for other airspace, can be customized or reset under **Settings → Airspace Colours**.

The neighboring-airspace contact section groups records by frequency, so differently named services sharing the same channel appear as one neutral card with all associated airspaces listed. Category colours are reserved for the map and are not repeated as contact-card highlights.

Runway markers use the selected CUP waypoint's `rwdir` true bearing and `rwlen` length in metres. The 3D local coordinate conversion maps north to `-Z` and east to `+X`; reciprocal headings are shown in the site details. Display width and height are intentionally exaggerated so runways remain visible at airspace scale, while heading and length stay accurate. No runway is invented when either heading or length is missing.

Airspace volumes have reinforced geometry-based upper and lower outlines with sparse vertical pillars. Circular boundaries are limited to eight highlighted pillars, avoiding the dense picket-fence effect while remaining clearly visible even on browsers that clamp WebGL line width to a single pixel.

Other Czech waypoints inside the current map display range are rendered as magenta map markers. Nearby airfield labels are shown selectively to prevent clutter, and the complete waypoint layer can be switched with **WPTS ON/OFF**. Its colour is customizable under **Settings → Airspace Colours → Nearby waypoints**. The selected airport-code label is shown only in **Labels All** mode. Waypoint, selected-site, compass and airspace labels use theme-aware foregrounds, opaque backing panels and reinforced borders so they remain legible in both themes.

The 3D pane uses OpenStreetMap tiles as an optional base plane under the airspace. A fresh profile starts in true orthographic **TOP** view with all labels, **AS ALL**, live traffic off, and the map off; the map-off base is a subtle grid without cardinal-letter sprites. Tile detail follows the camera from zoom level 10 through 17, and the close-range camera limit is 900 m, so taxiways, local roads, and airport surroundings remain useful after enabling the map. The camera is reset to the monitored airfield whenever a site is loaded. ISO remains a perspective volume view, while TOP uses separate flat airspace geometry without vertical walls or altitude perspective. Perspective and plan-view camera centers remain stable at close range, zooming is proportional, and panning follows screen direction after the view is rotated. Scene fog begins at 120 km and finishes at 340 km. Three.js, waypoint, airspace, and polygon-processing code are bundled locally; internet access is only required for map tiles, weather, and live traffic. Run the project through an HTTP server rather than opening `index.html` directly, because browsers do not permit `fetch()` of adjacent CUP/CUB files from `file://` pages.

The compact, equal-width controls above the viewer are grouped in display order: ISO/TOP view, map, airspace visibility, waypoints, labels, and live traffic. The north-up reset is a small compass overlay in the top-right of the map; its centred vector needle tracks rotation without wraparound animation. **AS ALL / AS ACTIVE** controls whether unconfirmed flexible airspace is visible and is mirrored under **Settings → Appearance**. Permanent published structures remain visible because the app has no tactical activation state for them. When a flexible volume is confirmed active, both modes render it only to the operational upper limit entered during confirmation. Each card in the Airspace menu has an eye control that hides or restores only that volume's map geometry and label; it remains selected and monitored for tracker classification. This declutter choice is retained separately for each site. The feet/metres converter is anchored at the bottom-left of the viewer, while the complete colour legend is under **Settings → Airspace Colours**. Airspace labels scale each row independently to fit their panels. Switching from split to full-width 3D recalculates the camera projection and widens map-tile coverage for the new viewport instead of stretching the narrow view.

The main **VIEW** control cycles through Split, Map, List, Tracker Split, and Tracker. Tracker modes use a north-up orthographic map, use the theme-aware variant of the locally generated **Minimal** treatment, omit airspace fills, place compact horizontal identification and vertical-limit labels along monitored-airspace boundaries, retain the monitored runway, and enlarge live tracker marks and labels. Their compact toolbar hides the fixed map, 2D/3D, label, and live controls, leaving airspace filtering and the functional **WPTS** toggle. Nearby waypoints appear when WPTS is active. The boundary-label layout tries several clear positions, prioritizes active and smaller local volumes over enclosing areas, and suppresses unavoidable collisions. Tracker Split places that presentation beside the normal aircraft board and uses compressed, non-wrapping aircraft column headings. Leaving tracker mode restores the previous normal camera, map, and live-traffic choices while preserving any waypoint choice made in Tracker view.

The viewport control strip overlays the map and fades after 3.2 seconds without pointer movement. Moving the pointer anywhere over the viewport restores it. The compass is a background-free floating arrow. A small detach control is normally tucked behind **VIEW** and slides out on hover; it opens Tracker, Map/3D, or Aircraft List in a separate resizable browser window suitable for another monitor. Detached and browser-fullscreen presentations suppress the top status strip. Each detached view includes a fullscreen toggle, while the detached Aircraft List retains a dedicated bottom add-aircraft bar. Aircraft, pools, timers, notes, location, activation state, and colour changes synchronize through same-origin browser storage.

Live traffic is available from the **LIVE** control and under **Settings → Live Traffic**. The companion server combines the open adsb.lol API with the bounded [OGN Live feed](https://github.com/glidernet/ogn-live/blob/master/README.md) every ten seconds. It requests only a Czech-sized source region and filters both feeds against a simplified Czech national boundary and a strict altitude limit below 10,000 ft; the browser repeats those safety filters before rendering. Outside traffic qualifies as **NEAR** only when it is no more than 3 km horizontally from the nearest selected-airspace boundary; the map display range is not used as a tracker catchment. Traffic horizontally inside a volume remains available as INSIDE, BELOW, or ABOVE. A live tracker assigned to a pool bypasses the local-distance test and continues to be followed anywhere in the Czech feed region. While live traffic is enabled, the compact top-strip tracker control shows a blue dot and the locally visible total only. At zero LOCAL targets it becomes a blinking blue dot with no text; click it to open ADS-B, OGN, feed-state, and refresh details. The control disappears completely when traffic is off. Map symbols use operational state rather than receiver source: green means inside a monitored volume and blue means outside, below, above, nearby, or pool-followed. ADS-B and OGN source labels share the same cyan treatment. Their bright outline, pulsing halo, label, and altitude stem render without depth occlusion, keeping targets visible through airspace and above the map. Position and altitude are smoothly interpolated, and aircraft headings orient the triangular symbols. **Labels All** adds callsign, source, state, altitude, and speed labels.

The bottom of **Active Traffic** contains an expandable **TRACKER** drawer. It lists every fresh target included in the monitored display: traffic inside a selected volume, traffic horizontally below or above one, traffic within 3 km of a selected boundary, and pool-followed traffic. Horizontal polygon containment (including holes) and the currently rendered vertical limits determine the state. Green **INSIDE** rows are within a monitored volume; blue **BELOW**, **ABOVE**, **NEAR**, and **FOLLOW** rows remain outside it. Rows queue as airborne INSIDE, BELOW, other nearby/outside states, a single grey expandable GND group, then user-hidden trackers. Each row has a labelled **HIDE/SHOW** eye control that suppresses only that target's map symbol and retains the row at the bottom for restoration. Narrow split panes hide secondary summary fields before allowing operational controls to clip, while the expanded telemetry automatically changes to two columns. Each target is normally a single compact line showing registration, state, source, type, altitude, speed, and airspace relationship. Raw receiver or tracker identifiers are never substituted for registration; when the dedicated field is missing, a valid Czech `OK...` callsign is normalized into registration format (for example, `OKRAD` becomes `OK-RAD`). Unavailable registrations display as **UNIDENT**. Selecting that line or its viewport marker expands only the matching row to show squawk, track, vertical rate, complete airspace status, note, and contact controls; clicking the expanded slot again collapses it. Split and Tracker Split keep the map free of the floating telemetry panel; Map-only and Tracker-only views retain it. On every completed tracker update, the top statistics box shows a brief subtle gradient sweep instead of a continuous progress bar. The sweep follows the box state: cyan normally and amber for a partial or retry state. The drawer refreshes with each ten-second tracker poll, and reports expire after 35 seconds. Polling pauses in a hidden tab, and the on/off preference is retained locally until the daily midnight reset.

The collapsed **Settings → Key** section contains both the tracker-stat key and map legend, keeping explanatory material out of the operational settings. It covers ADS-B, OGN, LOCAL, the state-matched update flash, state colours, ground targets, warning status, airspace colours, and waypoint symbols. **Settings → Appearance → Language** switches the operational interface between English and Czech; the selection follows the same local daily-memory lifecycle as the rest of the app.

The map button cycles through **MAP OFF**, a muted OpenStreetMap layer, and **MAP MINIMAL**. Minimal is generated locally from the same OpenStreetMap tiles and automatically switches between a restrained pale palette in Light theme and a very dark low-colour palette in Dark theme, so it does not depend on a second tile provider. Tracker mode follows the selected Light or Dark theme and uses a higher adaptive tile level plus a wider tile window, retaining smaller towns and secondary roads while suppressing most residential clutter. ISO orbiting can reach an almost exact overhead angle and pass slightly below the horizontal viewing plane for closer inspection of stacked volumes. In ISO, left-drag rotates, Shift+left-drag or middle-drag pans, and the wheel zooms; plan views use left-drag to pan. Right-drag is deliberately not a viewport control because Opera, Vivaldi, and gesture extensions can reserve it for browser-level new-tab, navigation, or close-tab actions that a webpage cannot safely override.

Selecting a live marker automatically opens and scrolls the compact **TRACKER** drawer beside **ADD POOL**, highlights and expands its live card and any linked operational card, and draws up to thirty minutes of its accumulated altitude-aware trail above all map and airspace geometry. Selecting a tracker row recentres the normal TOP/ISO viewport on that aircraft without changing zoom; Tracker and Tracker Split preserve their operational overview and only highlight it. In Tracker view, compact planar triangles point along each aircraft heading without a permanent white outline; selection draws a separated triangle outline and extends a steady forward heading vector instead of using a box or pulsing circle. Transparent, state-coloured aircraft, airspace, waypoint and airport labels are screen-scaled so their apparent size remains stable while zooming. Monitored-airspace boundaries use a slightly stronger line weight. The shared ADD POOL/TRACKER strip is reduced to a 23-pixel control height. Its abbreviated one-line field headings and ruled detail cells keep dense tracker data aligned. Tracker cards can be dragged directly into any traffic pool; the first note, contact reset, or pool move creates one linked operational aircraft row with a **TRACKER** badge, shared note, pool assignment, and contact timer. That operational slot is saved independently and remains occupied if the feed stops or the live report expires. Clicking either linked row reopens the detailed live report while one is available. Reports at zero ground speed are marked **GND**, grouped behind the grey GND dropdown, and omitted from the 3D while remaining available in the drawer. The tracker strip and drawer are absent while live tracking is disabled or no current flight is in the monitored display. A partial ADS-B/OGN outage is shown as an amber warning while the healthy feed continues; a fixed ten-second polling heartbeat and stalled-request watchdog recover without requiring a page reload.

Viewport labels, tracker rows, and the full telemetry panel all use the same normalized registration resolver. A registration change in a fresh report invalidates and rebuilds the map label. Ground/zero-altitude feed reports are classified at zero AGL, and a published zero-foot floor is treated explicitly as surface-reaching, preventing an impossible **BELOW CTR** state for CTR volumes beginning at GND.

Browser notifications also cover tracker-area entry. The first successful traffic fetch establishes a silent baseline; later aircraft crossing into a selected airspace's horizontal footprint or its 3 km tracker margin generate one system notification containing identity, source, altitude, and relationship to the monitored airspace. An aircraft must leave before the same identity can trigger another entry alert. Pool-only long-range retention and user-hidden trackers do not generate entry alerts. Permission is controlled by **Settings → Browser Notifications** and must be granted by the browser.

The lower information area contains a theme-responsive **Useful Links & Sources** section for the Czech aircraft register, AIM/AIP and NOTAM information, the Aeroklub ČR landing-fee memorandum, Windy, and AirGuru Předletovka. Links open in a separate tab and their labels follow the EN/CZ language setting.

This traffic layer is advisory and depends on receiver coverage, network availability, and delayed, missing, or erroneous reports. It must not be used for separation or collision avoidance.

The upstream traffic and weather services do not currently provide usable browser CORS access, so a plain static file server cannot deliver those live features. From this repository folder run `node radio-watch-server.js`, then open the exact address printed in the terminal—normally `http://127.0.0.1:8080`. If that port is occupied, the server automatically tries `8081` through `8089` and prints the selected address. Stop an obsolete instance with `Ctrl+C` in its terminal, and use a hard refresh after restarting. The app discards malformed older R4DIO DASH saved-state records instead of allowing them to interrupt startup. It serves the website plus cached same-origin `/api/live-traffic` and `/api/metars` endpoints; no npm install or API key is required. Separately deployed compatible endpoints can be selected with the `trafficEndpoint` and `metarEndpoint` query parameters. The rest of the app remains usable on GitHub Pages, but live traffic and METAR need a relay deployed alongside it.

METAR selection combines current reports from the [ŘLP ČR meteorological page](https://meteo.rlp.cz/) and AviationWeather.gov, preferring the ŘLP copy when both sources contain the same station. NIL reports are discarded. In automatic mode, an available report for the monitored airport wins; otherwise the app calculates the closest reporting airport using the local Czech waypoint coordinates. Clicking the METAR display opens its station menu; **CHOOSE METAR AIRPORT** expands all 17 supported Czech stations and clearly marks airports without a current report. A manual station choice persists until AUTO is selected again. Local and UTC clocks always use fixed `HH:MM:SS` formatting.

Operational memory is daily by design. At local midnight the app removes all `radioWatch*` and `rw_*` local/session storage—including traffic, pools, timers, notes, activation state, site selection, presets, shortcuts, display preferences, and manual METAR choice—and reloads with fresh defaults. An open app also detects the date change after sleep or on its next load. Storage belonging to unrelated websites or applications on the same origin is left untouched.

The app generates a 5.5 km ATZ from ground level to 4000 ft AMSL around every open Czech airport waypoint except LKPR, LKTB, LKMT, and LKKV. Published ATZ geometry is retained instead of duplicated. Generated boundaries are cut only by non-ATZ airspace that reaches the local surface; elevated volumes do not erase usable ATZ airspace below them, and drop zones never participate in ATZ subtraction. Fully surface-covered ATZs are omitted. The resulting multi-part shapes and holes remain selectable and are included in the normal airspace list. Drop zones use red boundary lines without a filled volume. Boolean geometry is provided locally by `polygon-clipping.min.js`, so ATZ generation does not depend on a runtime package CDN.

The contact page separates published frequencies for selected airspace from services belonging to its immediate horizontal neighbors. A neighbor must touch, overlap, or come within 1.5 km of at least one selected boundary; unrelated volumes elsewhere in the map display range are excluded. Praha Information frequencies are labelled by their published FIC sectors: Čechy West, Čechy East, and Morava. Immediate-neighbour frequencies come first, followed by the LKKO ATC phone contacts when applicable, then Emergency contacts. These dataset frequencies are a situational reference and must be checked against the current AIP, NOTAM and responsible ATS unit.

The location picker provides searchable waypoint and airspace lists plus a zoomable OpenStreetMap selection map. Its default list and map suggestions show Czech waypoint codes beginning with **LK**, keeping the initial choice focused on airports and published aviation locations. Searching queries all 767 Czech waypoints, so uncoded and non-LK points remain selectable when the user deliberately searches for them; a selected non-LK point stays visible after clearing the search. The map opens fitted to the complete Czech dataset plus every CUB airspace intersecting the Czech national extent. Use the mouse wheel or +/- controls to zoom, drag to pan, and use **FIT** to restore the national overview. Click a waypoint marker to change the reference site or click any airspace polygon to add/remove it from the monitored set. The selection content has its own scroll area, while status, Cancel, and **Apply Site** remain permanently visible at the bottom; the dataset and ENR reference notice closes the scrollable content beneath the map.

METAR reports refresh automatically every five minutes, immediately after network recovery, and when a suspended tab returns with data older than four minutes. Manual refresh remains available in the station menu.

### Airspace status model

The interface deliberately separates published geometry from operational status, following the bundled `enr_1_en.pdf` guidance:

- published limits and planned AUP/UUP allocation do not establish real activation;
- TRA, TSA, TFR, and TRA GA volumes must be explicitly confirmed active in the app;
- completing a TRA GA activation, vertical-limit adjustment, or deactivation shows a reminder to report the change to the designated operator; ordinary TRA/TSA changes do not trigger it;
- TSA excludes other traffic while active, whereas transit through TRA may be allowed under ATC clearance;
- real-time status information is shown as requiring reconfirmation after 15 minutes;
- TRA GA activation requires the coordinated upper boundary, accepted as either a flight level (`FL95` or `95`) or an AMSL altitude (`4500 ft`), and is checked against the published limits;
- the app never silently infers a flexible volume to be free from a schedule.

This remains an operational aid with non-guaranteed data. Always verify current AIP, AUP/UUP, NOTAM, and responsible ATS-unit information.

### Data parser

`aviation-data.js` implements the official Naviter CUP and CUB formats in the browser. It reads compressed CUB polygons, classes/types, altitude reference systems, names, frequencies, and activation flags. `polygon-clipping.min.js` performs local polygon subtraction for generated ATZ boundaries. The original hard-coded LKKO geometry remains available as a safe visual fallback when the bundled datasets cannot be loaded.
